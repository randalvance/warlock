# ADR 0002: Nx runs the workspace tasks

- Status: accepted
- Date: 2026-11-07

## Context

`pnpm -r` ran each app's script on every call and stored no result, so a second `pnpm typecheck` with no file changes did all the work again. A cache needs to know which files each task reads, and the web typecheck reads server files as well as its own.

## Decision

Nx 24 runs the tasks. pnpm still installs packages and owns the workspace list in `pnpm-workspace.yaml`.

| Concern | Choice |
| --- | --- |
| Targets | Nx reads each app's `package.json` scripts as targets. There is no `project.json` and no Nx plugin. |
| Project names | The package names, `@warlock/server` and `@warlock/web`. The repo root is not a project, so a root script can call `nx` without calling itself. |
| Cache | `nx.json` caches `typecheck`, `test`, and `db:check`. A task's hash covers its app's files and `tsconfig.base.json`. Nx keeps the cache in `~/.nx/<workspace id>/cache`, outside the repo. In the dev container that is the container's home folder. The repo's `.nx/` holds only the project graph, and git ignores it. |
| Typecheck inputs | The `typecheck` hash also covers the files of every app it depends on. The web typecheck reads server source through `@warlock/server/api`, so a server change must rerun it. |
| Outside Nx | `pnpm lint` and `pnpm format` run Biome once over the whole repo, because no app owns the root files. `pnpm smoke` runs Playwright from the root, because it starts both apps. |
| Nx Cloud and analytics | Off. `neverConnectToCloud` stops Nx from offering Nx Cloud. `analytics: false` stops the usage-data prompt that otherwise blocks the first run in a terminal. |

## Consequences

- To run one app's script, use `pnpm nx run <project>:<script>`.
- A new script in an app's `package.json` becomes a target with no other change. It is cached only after `nx.json` lists it under `targetDefaults`.
- The root `.env` sets `NX_LOAD_DOT_ENV_FILES=false`. Without it, Nx loads the root `.env` into every task, and it also loads an app's own `.env`, `.env.local`, or `.local.env` into that app's tasks only. A `WARLOCK_PORT` in `apps/server/.env.local` would then move the server but not the web proxy. With the setting, Nx loads no dotenv file into a task, and the server and Vite read the root `.env` themselves, as they did before Nx.
- Nx still deletes a shell variable from a task's environment when its value equals one in the root `.env`, `.env.local`, or `.local.env`, whatever `NX_LOAD_DOT_ENV_FILES` says. For the root `.env` the result is the same, because the apps read that file and get the same value back. Keep no root `.env.local` or `.local.env`. The apps never read them, and a shell value that matches one never reaches the app.
- Playwright starts Vite with `pnpm --filter @warlock/web dev`, not through Nx, so the ports it passes always reach Vite.
- Nx prints the output of a failed task and hides the output of a task that passes. Add `--output-style=static` to see all of it.
- If Nx finds an AI agent's variable in its environment, such as `CLAUDECODE`, it prints only the path of each failed task's log. `devcontainer exec` does not pass these variables into the container, so this happens only when Nx runs outside it. Add `--output-style=static` to print the log inline.
- CI starts each run with an empty cache, so CI runs every task. Storing the Nx cache between runs, or running only the tasks a change affects, is a later decision.

## Alternatives considered

- **Keep `pnpm -r`.** It has no cache and no graph, which are the reasons for this change.
- **Nx plugins such as `@nx/vite` and `@nx/js`.** They infer targets from tool config files. The scripts already name every command, so plugins would add packages and a second place where targets come from.
- **Put lint under Nx as one task per app.** Biome checks the whole repo in about a tenth of a second, so a cache saves nothing. The root files would also need a project of their own.
