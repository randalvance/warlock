# ADR 0002: Nx runs the workspace tasks

- Status: accepted
- Date: 2026-11-07

## Context

`pnpm -r` ran each app's script on every call and stored no result, so a second `pnpm typecheck` with no file changes did all the work again. A cache needs to know which files each task reads, and the web typecheck reads server files as well as its own.

## Decision

Nx 24 runs the tasks. pnpm still installs packages and owns the workspace list in `pnpm-workspace.yaml`.

| Concern | Choice |
| --- | --- |
| Targets | Nx reads each app's `package.json` scripts as targets. There is no `project.json` and no Nx plugin. |
| Project names | The package names, `@warlock/server` and `@warlock/web`. The repo root is not a project, so a root script can call `nx` without calling itself. |
| Cache | `nx.json` caches `typecheck`, `test`, and `db:check`. A task's hash covers its app's files and `tsconfig.base.json`. The cache lives in `.nx/`, which git ignores. |
| Typecheck inputs | The `typecheck` hash also covers the files of every app it depends on. The web typecheck reads server source through `@warlock/server/api`, so a server change must rerun it. |
| Outside Nx | `pnpm lint` and `pnpm format` run Biome once over the whole repo, because no app owns the root files. `pnpm smoke` runs Playwright from the root, because it starts both apps. |
| Nx Cloud | Off. `neverConnectToCloud` stops Nx from offering it. |

## Consequences

- To run one app's script, use `pnpm nx run <project>:<script>`.
- A new script in an app's `package.json` becomes a target with no other change. It is cached only after `nx.json` lists it under `targetDefaults`.
- Nx loads the root `.env` into the environment of every task, so tasks see `WARLOCK_PORT=4317`. A variable already set in the shell wins. The Playwright config sets its own ports, so the browser tests still use 4417 and 5273.
- Nx prints the output of a failed task and hides the output of a task that passes. Add `--output-style=static` to see all of it.
- CI starts each run with an empty cache, so CI runs every task. Storing `.nx/cache` between runs, or running only the tasks a change affects, is a later decision.

## Alternatives considered

- **Keep `pnpm -r`.** It has no cache and no graph, which are the reasons for this change.
- **Nx plugins such as `@nx/vite` and `@nx/js`.** They infer targets from tool config files. The scripts already name every command, so plugins would add packages and a second place where targets come from.
- **Put lint under Nx as one task per app.** Biome checks the whole repo in about a tenth of a second, so a cache saves nothing. The root files would also need a project of their own.
